## طراحی

یک UART کامل (فرستنده + گیرنده)، و سپس **دو واحد وصل‌شده به هم** برای نمایش مبادله‌ی دوطرفه.

| ماژول | نقش |
|--------|------|
| `rtl/uart_pkg.vh` | قالب فریم و ثابت‌ها |
| `rtl/baud_gen.v` | پالس نمونه‌برداری با نرخ ۱۶ برابر نرخ بیت |
| `rtl/uart_tx.v` | فرستنده (`IDLE`/`START`/`PARITY`/`DATA`/`STOP`) |
| `rtl/uart_rx.v` | گیرنده (`IDLE`/`START`/`RECV`/`STOP`/`RESYN`) |
| `rtl/uart.v` | یک واحد کامل دوطرفه‌ی هم‌زمان (یک شمارنده، دو مسیر) |
| `rtl/uart_link.v` | دو واحد وصل‌شده به یکدیگر |

### قالب فریم

```
idle | START | PARITY | D6 D5 D4 D3 D2 D1 D0 | STOP | idle
  1  |   0   |   P    |     7 data bits      |   1  |  1
     <--------------- 10 bit times --------------->
             <--- 8 bits the receiver stores --->
```

دو نکته که از صورت آزمایش می‌آید و با UART استاندارد فرق دارد:

- بیت **توازن قبل از داده** فرستاده می‌شود ⇒ فرستنده باید کل کاراکتر را پیش از شروع داشته باشد (بارگذاری موازی، توازن ترکیبی).
- داده **MSB‌اول** فرستاده می‌شود تا ثبات ۸ بیتی گیرنده دقیقا `{parity, D6..D0}` شود؛ با LSB‌اول کد ASCII برعکس ذخیره می‌شد و به یک معکوس‌کننده‌ی بیتی نیاز بود.

### واسط `uart`

| سیگنال | جهت | پهنا | توضیح |
|--------|------|------|--------|
| `tx_start` / `tx_data` | ورودی | ۱ / ۷ | درخواست ارسال یک کد ASCII |
| `txd` | خروجی | ۱ | خط سریال خروجی (بی‌کار = ۱) |
| `tx_busy` / `tx_done` | خروجی | ۱ | درخواست در میانه‌ی فریم **نادیده** گرفته می‌شود |
| `rxd` | ورودی | ۱ | خط سریال ورودی |
| `rx_reg` | خروجی | ۸ | `{parity, D6..D0}` |
| `rx_data` | خروجی | ۷ | همان، فقط کد ASCII |
| `rx_valid` | خروجی | ۱ | یک پالس تک‌کلاکی در پایان هر فریم |
| `parity_err` / `frame_err` | خروجی | ۱ | داده **حتی با خطا** هم ذخیره می‌شود |

### نکته‌های گیرنده

- **هم‌گام‌ساز دو فلیپ‌فلاپی** روی `rxd` (ورودی ناهم‌گام).
- پس از پایین آمدن خط، **نیم بیت** صبر و بررسی دوباره ⇒ سوزن نویزی به‌جای بیت شروع گرفته نمی‌شود.
- نمونه‌برداری **وسط بیت** ⇒ بیشترین تحمل نسبت به اختلاف نرخ دو طرف.
- بیت خاتمه‌ی خراب ⇒ حالت `RESYN` تا بی‌کار شدن خط، وگرنه همان صفر به‌عنوان بیت شروع بعدی خوانده می‌شد.

### حاشیه‌ی خطای نرخ بیت

آخرین نمونه (بیت خاتمه) ۹٫۵ بیت بعد از نقطه‌ی هم‌گامی گرفته می‌شود و تا وقتی درست است که رانش انباشته از نصف بیت بیشتر نشود:

```
حد نظری = 0.5 / 9.5 ≈ 5.3٪
```

اندازه‌گیری‌شده روی همین مدار: تا **۵٪** همه‌ی کاراکترها سالم می‌رسند، از **۶٪** به بعد هیچ‌کدام. تست لینک روی ۵٪ (نسبت تقسیم ۲۰ و ۲۱) اجرا می‌شود — درست زیر حد.

### ⚠ اشکالی که با اندازه‌گیری پیدا شد

«نمونه‌برداری از وسط بیت» ادعایی است که به‌راحتی اشتباه پیاده‌سازی می‌شود و **هیچ تستی را رد نمی‌کند** — فقط حاشیه‌ی تحمل را بی‌سروصدا کم می‌کند. پس نقطه‌ی نمونه‌برداری مستقیم اندازه‌گیری شد (شمارش `os_tick` از لبه‌ی شروع تا لحظه‌ی ذخیره‌ی هر بیت):

| | نقاط نمونه‌برداری | ایده‌آل |
|---|---|---|
| اول | `26, 42, 58, ...` | `24, 40, 56, ...` |
| پس از اصلاح | `25, 41, 57, ...` | `24, 40, 56, ...` |

علت: خطای واحد در شمارنده‌ی نیم‌بیت.

```verilog
if (os == OS/2)      // ❌ os از صفر شروع و قبل از افزایش تست می‌شود ⇒ OS/2+1 تیک
if (os == OS/2 - 1)  // ✅ شمردن 0..OS/2-1 دقیقا OS/2 تیک است
```

یک تیک باقی‌مانده اجتناب‌ناپذیر است (شمارنده فقط روی مرز پالس‌ها شروع می‌شود ⇒ همان خطای `1/16` بیت). **اثرش کم نبود:** پیش از اصلاح، لینک با ۵٪ اختلاف نرخ کاراکتر گم می‌کرد.
