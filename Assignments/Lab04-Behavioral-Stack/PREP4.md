## اصلا این آزمایش چیست؟ (۳۰ ثانیه اول ارائه)

آزمایش قبل (Lab 03) می‌گفت مدار را با **`assign`** بنویس؛ یعنی خودت باید معادلات منطقی را در می‌آوردی.

این آزمایش می‌گوید همان کار را با **توصیف رفتاری (behavioral)** انجام بده:  
به جای نوشتن معادله، فقط **رفتار** مدار را با `always` بیان می‌کنی و بقیه‌اش با ابزار سنتز است.

چیزی که باید بسازیم: یک **پشته (Stack)** با عمق ۸ و پهنای ۴ بیت.

### پشته یعنی چه؟

پشته یعنی `LIFO` = **Last In, First Out**.  
دقیقا مثل یک دسته بشقاب روی هم:

- بشقاب جدید را می‌گذاری **روی** دسته → این می‌شود `Push`
- بشقاب را از **روی** دسته برمی‌داری → این می‌شود `Pop`

هرچه **آخر** گذاشتی، **اول** برمی‌داری. این تنها چیزی است که باید حفظ کنی.

## واسط مدار (روی این جدول انگشت بگذار)

| سیگنال | جهت | پهنا | کارش چیست |
|--------|------|------|-----------|
| `Clk` | ورودی | ۱ | کلاک؛ همه‌چیز روی لبه‌ی بالارونده اتفاق می‌افتد |
| `RstN` | ورودی | ۱ | ریست ناهم‌گام **فعال‌پایین**؛ پشته را خالی می‌کند |
| `Data_In` | ورودی | ۴ | داده‌ای که می‌خواهی Push کنی |
| `Push` | ورودی | ۱ | فرمان گذاشتن |
| `Pop` | ورودی | ۱ | فرمان برداشتن |
| `Data_Out` | خروجی | ۴ | چیزی که الان روی سر پشته است |
| `Full` | خروجی | ۱ | ۱ یعنی پشته پر است |
| `Empty` | خروجی | ۱ | ۱ یعنی پشته خالی است |

### چرا `RstN` فعال‌پایین است؟

چون حرف **N** آخرش یعنی `Not` / `active-low`. این قرارداد استاندارد است.  
یعنی وقتی `RstN = 0` مدار ریست می‌شود، نه وقتی ۱.

در کد اینطور نوشته شده:
```verilog
always @(posedge Clk or negedge RstN)
    if (!RstN) ...
```

### ⚠ نکته‌ای که ممکن است TA بپرسد

در صورت آزمایش نوشته شده:
```
Empty=0 indicates that the stack is empty
```
ولی سطر بالاترش نوشته:
```
Full=1 indicates that the stack is full
```

این دو با هم **ناسازگارند**. اگر `Empty=0` یعنی خالی، آنگاه اسم سیگنال باید `Not_Empty` می‌بود نه `Empty`.

**چه بگویی:** قرارداد متعارف و متقارن با `Full` را گرفتم، یعنی `Empty=1` وقتی پشته خالی است. اگر دقیقا همان متن صورت مدنظر باشد فقط کافی است خروجی را معکوس کنم — یک `~` است.

این نکته در گزارش هم صریحا نوشته شده.

## مدار داخلش چطور کار می‌کند؟

فقط **دو چیز** داخل ماژول هست:

```verilog
reg [3:0] mem [0:7];   // ۸ خانه‌ی ۴بیتی = خود پشته
reg [3:0] sp;          // اشاره‌گر پشته
```

### `sp` دقیقا چیست؟ (مهم‌ترین نکته‌ی ارائه)

`sp` = **تعداد کلمات معتبری که الان داخل پشته است**.  
یعنی شمارنده، نه اندیس.

این انتخاب باعث می‌شود همه‌چیز خیلی ساده شود:

| چیز | فرمول |
|-----|--------|
| خالی است؟ | `sp == 0` |
| پر است؟ | `sp == 8` |
| سر پشته کجاست؟ | `mem[sp-1]` |
| Push بعدی کجا بنویسد؟ | `mem[sp]` |

مثال — وقتی `sp = 5`:

```
mem[7]  ← خالی
mem[6]  ← خالی
mem[5]  ← خالی    ← Push بعدی اینجا می‌نویسد  (mem[sp])
mem[4]  ← پر      ← سر پشته، همین می‌رود روی Data_Out  (mem[sp-1])
mem[3]  ← پر
mem[2]  ← پر
mem[1]  ← پر
mem[0]  ← پر
```

### چرا `sp` چهار بیت است و نه سه؟

**این را حتما حفظ کن، سوال کلاسیک TA است.**

`sp` باید بتواند مقدارهای `0` تا `8` را نگه دارد — یعنی **۹ حالت مختلف**.

- با ۳ بیت فقط `0..7` می‌شود ← عدد ۸ سرریز می‌کند و می‌شود `0`
- نتیجه: پشته‌ی **پر** با پشته‌ی **خالی** اشتباه گرفته می‌شود! (فاجعه)

پس پهنا `$clog2(DEPTH) + 1` است = `3 + 1` = ۴ بیت.

جمله‌ی آماده: چون `sp` شمارنده است و باید خود عدد ۸ را هم نشان بدهد، یک بیت بیشتر از `log2(8)` لازم دارد.

## چهار حالت مرزی (بیشترین سوال از اینجاست)

| اگر... | چه می‌شود | چرا |
|--------|-----------|-----|
| `Push` بزنی و پشته **پر** باشد | نادیده گرفته می‌شود | جلوگیری از overflow؛ داده‌ی قدیمی خراب نشود |
| `Pop` بزنی و پشته **خالی** باشد | نادیده گرفته می‌شود | جلوگیری از underflow؛ `sp` منفی نشود |
| `Push` و `Pop` **هم‌زمان** | هیچ اتفاقی نمی‌افتد | دو فرمان متناقض؛ امن‌ترین تفسیر |
| هیچ‌کدام فعال نباشد | حالت حفظ می‌شود | — |

در کد این‌ها در دو خط خلاصه شده‌اند:

```verilog
wire do_push = Push & ~Pop & ~Full;
wire do_pop  = Pop  & ~Push & ~Empty;
```

**اگر TA پرسید چرا Push+Pop هم‌زمان no-op است؟**  
بگو: می‌شد رفتار `replace top` (جایگزینی سر پشته) هم گذاشت، ولی صورت آزمایش این دو را دو فرمان **مستقل** تعریف کرده و درباره‌ی ترکیبشان چیزی نگفته. پس تفسیر محافظه‌کارانه‌ی بدون‌تغییر را انتخاب کردم و در تست‌بنچ هم صریحا تستش کردم.

## کد اصلی — دو بلوک `always` و تمام

### بلوک ۱: ترتیبی (حافظه و اشاره‌گر)

```verilog
always @(posedge Clk or negedge RstN) begin
    if (!RstN) begin
        sp <= 0;                  // ریست: پشته خالی
        for (i=0; i<DEPTH; i=i+1)
            mem[i] <= 0;
    end else begin
        if (do_push) begin
            mem[sp] <= Data_In;   // بنویس روی خانه‌ی خالی بعدی
            sp      <= sp + 1;    // یکی بالاتر برو
        end else if (do_pop) begin
            sp <= sp - 1;         // فقط یکی پایین بیا
        end
    end
end
```

**نکته‌ی خوب برای گفتن:** موقع `Pop` اصلا حافظه پاک نمی‌شود، فقط `sp` کم می‌شود. داده‌ی قدیمی همان‌جا می‌ماند ولی نامعتبر حساب می‌شود و `Push` بعدی رویش می‌نویسد. این دقیقا کاری است که پشته‌ی واقعی می‌کند.

### بلوک ۲: ترکیبی (خروجی داده)

```verilog
always @(*) begin
    if (sp == 0) Data_Out = 0;      // پشته خالی → صفر
    else         Data_Out = mem[sp-1];  // وگرنه سر پشته
end
```

چرا `always @(*)` و نه `assign`؟ چون آزمایش گفته توصیف **رفتاری**؛ پس کل ماژول را با `always` نوشتم که سبک یکدست بماند.

### پرچم‌ها

```verilog
assign Empty = (sp == 0);
assign Full  = (sp == DEPTH);
```

## مثال کامل روی کاغذ (این را حفظ کن)

فرض کن `Push` می‌زنی با `3`، بعد `7`، بعد یک `Pop`:

| کلاک | فرمان | `sp` بعدش | `Data_Out` | `Empty` | `Full` |
|------|--------|-----------|------------|---------|--------|
| ۰ | ریست | 0 | 0 | **1** | 0 |
| ۱ | Push 3 | 1 | **3** | 0 | 0 |
| ۲ | Push 7 | 2 | **7** | 0 | 0 |
| ۳ | Pop | 1 | **3** | 0 | 0 |
| ۴ | Pop | 0 | 0 | **1** | 0 |
| ۵ | Pop | 0 | 0 | 1 | 0 |

سطر آخر مهم است: `Pop` روی پشته‌ی خالی هیچ کاری نکرد — `sp` منفی نشد.

## اگر TA سوال پیچید

**فرق توصیف رفتاری با جریان داده چیست؟**  
جریان داده = خودت معادله‌ی منطقی می‌نویسی (`assign`). رفتاری = فقط رفتار را توصیف می‌کنی (`always`) و ساخت حافظه/شمارنده/منطق کنترلی با ابزار سنتز است. پیاده‌سازی پشته در سطح گیت کار سنگینی است ولی رفتاری در چند خط تمام می‌شود.

**چرا `<=` استفاده کردی نه `=`؟**  
داخل بلوک ترتیبی (`posedge`) باید انتساب غیرمسدودکننده (`<=`) باشد تا همه‌ی رجیسترها هم‌زمان و بر اساس مقدار قبلی به‌روز شوند. در بلوک ترکیبی (`always @(*)`) برعکس، `=` درست است.

**این پشته چند کلاک تأخیر دارد؟**  
نوشتن یک کلاک طول می‌کشد (روی لبه)، ولی خواندن **ترکیبی** است — `Data_Out` همیشه بدون تأخیر سر پشته را نشان می‌دهد.

**اگر هم‌زمان Push و Pop لازم شد چه؟**  
باید در صورت مسئله مشخص می‌شد. اگر بخواهند `replace top`، فقط کافی است شرط را عوض کنم: `mem[sp-1] <= Data_In` بدون تغییر `sp`.

**موقع Pop چرا حافظه را پاک نکردی؟**  
لازم نیست. `sp` تعیین می‌کند کدام خانه‌ها معتبرند؛ داده‌ی بازمانده هرگز خوانده نمی‌شود و `Push` بعدی رویش می‌نویسد. پاک‌کردنش فقط منطق اضافه می‌آورد.

**چرا وقتی خالی است `Data_Out` صفر است؟**  
یک انتخاب طراحی برای معین بودن خروجی است؛ می‌شد `x` هم گذاشت. مهم این است که وقتی `Empty=1` است، مصرف‌کننده اصلا نباید به `Data_Out` اعتماد کند.
