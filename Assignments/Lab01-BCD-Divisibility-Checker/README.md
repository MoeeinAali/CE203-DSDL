# Lab 01 — تشخیص مضرب ۳ و مضرب ۱۱ بودن یک عدد BCD چهاررقمی

مدار **ترکیبی** (بدون فلیپ‌فلاپ، بدون کلاک) که یک عدد BCD چهاررقمی (`D3 D2 D1 D0`، هر رقم ۴ بیت، مقدار کل بین `0000` تا `9999`) را می‌گیرد و یک خروجی تک‌بیتی می‌دهد که وقتی عدد مضربی از ۳ (آزمایش اول) یا مضربی از ۱۱ (آزمایش دوم) باشد ۱ می‌شود. طبق متن آزمایش («در طراحی این مدار فقط مجاز به استفاده از گیت‌های پایه هستید» — آزمایش اول، دستور کار آزمایشگاه طراحی سیستم‌های دیجیتال، ص ۷) **در کل مدار فقط از گیت‌های AND / OR / XOR / NOT استفاده شده** — نه از تراشه، نه از قطعه‌ی آماده‌ی `Adder`/`Comparator` کتابخانه‌ی Arithmetic لاجیسیم.

| | |
|---|---|
| فایل مدار | [`bcd_divisibility.circ`](bcd_divisibility.circ) |
| مدارهای اصلی | `mod3_checker`، `mod11_checker` (خروجی هرکدام دقیقاً همان چیزی که آزمایش خواسته) |
| مدار دمو | `main` — هر دو چک‌کننده روی همان ۴ ورودی مشترک، برای مشاهده‌ی هم‌زمان دو خروجی |
| بلوک‌های پایه | `full_adder` (۵ گیت)، `adder4`/`adder5` (زنجیره‌ی `full_adder`)، `cmp3` (۱۷ گیت)، `eq5` (۱۴ گیت) |
| گیت‌ها | فقط `AND Gate`, `OR Gate`, `XOR Gate`, `NOT Gate` — در کل پروژه هیچ گیت دیگری، هیچ تراشه‌ای، و هیچ قطعه‌ی حسابی آماده‌ای به کار نرفته |
| تست | ۱۰/۱۰ مجموعه‌تست پاس؛ `mod3_checker` و `mod11_checker` هرکدام روی **تمام ۱۰۰۰۰ حالت ممکن** `0000..9999` به‌صورت جامع تست شده‌اند |

## رابط

`mod3_checker` و `mod11_checker` رابط یکسانی دارند:

| سیگنال | جهت | پهنا | توضیح |
|---|---|---|---|
| `D0` | ورودی | ۴ | رقم یکان (کم‌ارزش‌ترین رقم) |
| `D1` | ورودی | ۴ | رقم دهگان |
| `D2` | ورودی | ۴ | رقم صدگان |
| `D3` | ورودی | ۴ | رقم هزارگان (پرارزش‌ترین رقم) |
| `out` | خروجی | ۱ | ۱ اگر عدد `D3D2D1D0` مضربی از ۳ (یا ۱۱) باشد |

مقدار هر رقم باید یک کد BCD معتبر (`0..9`) باشد؛ مدار برای این بازه طراحی و به‌صورت جامع تست شده است.

## چرا اصلاً می‌شود این را بدون FSM حل کرد

چون مدار باید **ترکیبی محض** باشد (نه ترتیبی، نه بیت‌به‌بیت سریال)، به‌جای پیاده‌سازی یک ماشین‌حالت «باقیمانده mod 3 / mod 11» و باز کردنش روی ۱۶ بیت، از دو اتحاد عددی مربوط به مبنای ۱۰ استفاده شده که مسئله را به یک جمع رقم‌ها و یک مقایسه‌ی کوچک تبدیل می‌کند. هر دو اتحاد پیش از ساخت حتی یک گیت، با یک اسکریپت پایتون روی **هر ۱۰۰۰۰ مقدار BCD** به‌صورت brute-force راستی‌آزمایی شدند (صفر مورد نقض).

### مضرب ۳: جمع ارقام

چون `10 ≡ 1 (mod 3)`، هر توان ۱۰ هم `≡ 1 (mod 3)` است، پس:

```
N = D3·1000 + D2·100 + D1·10 + D0  ≡  D3+D2+D1+D0   (mod 3)
```

یعنی کافی است رقم‌ها را جمع بزنیم (`S`, بین ۰ تا ۳۶، در ۶ بیت جا می‌شود) و بررسی کنیم `S` مضرب ۳ هست یا نه — دقیقاً همان ترفند معروف «تقسیم‌پذیری بر ۳ از روی جمع ارقام»، اما این‌بار خود `S` هم باید بدون شمارنده و بدون تقسیم چک شود. برای این کار از وزن دودویی استفاده می‌شود: چون `2 ≡ -1 (mod 3)`، وزن بیت `k`ام برابر `2^k mod 3` است که بین `+1` (بیت‌های زوج: ۰و۲و۴) و `-1` (بیت‌های فرد: ۱و۳و۵) نوسان می‌کند. پس اگر

```
P = s0 + s2 + s4      (مجموع بیت‌های زوج S، بین ۰ تا ۳)
Q = s1 + s3 + s5      (مجموع بیت‌های فرد S، بین ۰ تا ۳)
```

آنگاه `S ≡ P - Q (mod 3)`، و شرط `S mod 3 = 0` می‌شود `P mod 3 = Q mod 3`. چون `P,Q ∈ {0,1,2,3}` این فقط دو حالت دارد: `P = Q`، یا `{P,Q} = {0,3}` (چون `3 ≡ 0`). این دقیقاً همان کاری‌ست که بلوک `cmp3` انجام می‌دهد. جالب اینکه محاسبه‌ی خود `P` و `Q` (جمع سه بیت تکی) چیزی نیست جز یک **تمام‌جمع‌کننده** دیگر — `full_adder(s0,s2,s4)` مستقیماً `{p1,p0}` را می‌دهد.

### مضرب ۱۱: جمع متناوب ارقام

چون `10 ≡ -1 (mod 11)`:

```
N ≡ -D3 + D2 - D1 + D0 = (D0+D2) - (D1+D3)   (mod 11)
```

با `A = D0+D2` و `B = D1+D3` (هرکدام بین ۰ تا ۱۸)، بازه‌ی `A-B` بین `-18` تا `+18` است؛ تنها مضرب‌های ۱۱ در این بازه `-11, 0, +11` هستند. پس:

```
N mod 11 = 0   ⇔   A+11 = B   یا   A = B   یا   A = B+11
```

سه مقایسه‌ی تساوی که با جمع‌کننده (برای `A+11` و `B+11`) و کامپریتور تساوی (`eq5`) پیاده می‌شوند — بدون هیچ کم‌کننده یا مکمل‌دوی صریح.

## ردیابی دستی (برای ارائه)

**مثال ۱ — `N = 132`** (هم مضرب ۳ است، هم مضرب ۱۱): `D3D2D1D0 = 0 1 3 2`

| گام | `mod3_checker` | `mod11_checker` |
|---|---|---|
| ورودی | `D0=2, D1=3, D2=1, D3=0` | همان |
| جمع | `S = 2+3+1+0 = 6 = 000110₂` | `A = D0+D2 = 2+1 = 3` , `B = D1+D3 = 3+0 = 3` |
| کاهش | `P=s0+s2+s4=0+1+0=1` , `Q=s1+s3+s5=1+0+0=1` | `A = B` ⇒ `eq2=1` |
| مقایسه | `P=Q=1` ⇒ `cmp3=1` | `eq1=eq3=0`, `out = eq1∨eq2∨eq3 = 1` |
| نتیجه | `out=1` ✓ (`132/3=44`) | `out=1` ✓ (`132/11=12`) |

**مثال ۲ — `N = 133`** (نه مضرب ۳، نه مضرب ۱۱): `D3D2D1D0 = 0 1 3 3`

| گام | `mod3_checker` | `mod11_checker` |
|---|---|---|
| جمع | `S = 3+3+1+0 = 7 = 000111₂` | `A = 3+1 = 4` , `B = 3+0 = 3` |
| کاهش | `P=s0+s2+s4=1+1+0=2` , `Q=s1+s3+s5=1+0+0=1` | `A≠B`, `A+11=15≠3`, `B+11=14≠4` |
| نتیجه | `P=2 ≠ Q=1` ⇒ `out=0` ✓ | `eq1=eq2=eq3=0` ⇒ `out=0` ✓ |

## معماری سلسله‌مراتبی

هر بلوک یک مدار مستقل با `<appear>` سفارشی است (یعنی وقتی داخل مدار بالادستی جای می‌گیرد، فقط یک جعبه‌ی کوچک با پین‌های لیبل‌دار دیده می‌شود، نه انبوه گیت داخلش) — دقیقاً همان تکنیکی که در `full_adder`/`adder2` پروژه‌ی CE103-CAL/Lab02 دیده می‌شود.

| بلوک | ورودی → خروجی | ساخته‌شده از | گیت خام |
|---|---|---|---|
| `full_adder` | `A,B,Cin → S,Cout` | `X1=A⊕B`, `P1=A·B`, `S=X1⊕Cin`, `P2=X1·Cin`, `Cout=P1+P2` | ۲XOR + ۲AND + ۱OR = ۵ |
| `adder4` | `A[4],B[4] → S[5]` | ۴ نمونه‌ی `full_adder` زنجیره‌ای (ripple)، `Cin` بیت صفر به GND | ۴×۵ = ۲۰ |
| `adder5` | `A[5],B[5] → S[6]` | ۵ نمونه‌ی `full_adder` زنجیره‌ای | ۵×۵ = ۲۵ |
| `cmp3` | `p1,p0,q1,q0 → Eq` | `P mod3 = Q mod3` (فرمول بالا) | ۲XOR + ۶NOT + ۷AND + ۲OR = ۱۷ |
| `eq5` | `A[5],B[5] → Eq` | ۵×`NOT(Ai⊕Bi)` سپس درخت AND | ۵XOR + ۵NOT + ۴AND = ۱۴ |

### `mod3_checker` — ۹۲ گیت خام (روی همه‌ی بلوک‌ها باز شود)

```
D0,D1 ──▶ adder4 "AB" ──▶ Sab[5] ─┐
D2,D3 ──▶ adder4 "CD" ──▶ Scd[5] ─┴─▶ adder5 "SUM" ──▶ S[6] (=۰..۳۶)
                                                          │
                                S0,S2,S4 ──▶ full_adder "P" ──▶ p1,p0 ─┐
                                S1,S3,S5 ──▶ full_adder "Q" ──▶ q1,q0 ─┴─▶ cmp3 ──▶ out
```

۲×`adder4`(۲۰) + ۱×`adder5`(۲۵) + ۲×`full_adder`(۱۰) + ۱×`cmp3`(۱۷) = **۹۲ گیت**.

### `mod11_checker` — ۱۳۶ گیت خام

```
D0,D2 ──▶ adder4 "A" ──▶ A[5] ──▶ adder5 "AP11" (+۱۱) ──▶ AP[5] ─┐
D1,D3 ──▶ adder4 "B" ──▶ B[5] ──▶ adder5 "BP11" (+۱۱) ──▶ BP[5] ─┤
                                                                    ├─▶ eq5"EQ1"(AP,B) ─┐
                                          A[5], B[5] ───────────────┼─▶ eq5"EQ2"(A,B)  ─┼─▶ OR ─▶ OR ─▶ out
                                          A[5], BP[5] ──────────────┴─▶ eq5"EQ3"(A,BP) ─┘
```

۲×`adder4`(۴۰) + ۲×`adder5`(۵۰) + ۳×`eq5`(۴۲) + ۲ گیت `OR` نهایی = **۱۳۶ گیت**.

عدد ثابت ۱۱ (`= 01011₂`) با ۵ قطعه‌ی `Constant` تک‌بیتی مستقیماً به ورودی `B` هر `adder5` وصل شده — نه از قطعه‌ی `Adder`ی آماده و نه از باس چندبیتی ثابت.

## چیدمان و سیم‌کشی

- هر رقم ورودی (`Pin` ۴بیتی) بلافاصله با یک `Splitter` به ۴ بیت تکی می‌شکند و هر بیت با یک سیم کوتاه به یک تونل نام‌دار می‌رود (`D0B0`..`D0B3` و..)؛ از همان‌جا به بعد **هیچ باس چندبیتی داخلی نداریم** — تمام محاسبات با سیم‌های تک‌بیتی انجام می‌شود، دقیقاً برای اینکه هیچ‌جا لازم نباشد سیم‌های عریض از وسط مدار رد شوند.
- هر اتصال «راه‌دور» (بین دو بلوک، یا بین دو طبقه‌ی گیت داخل `cmp3`/`eq5`) از یک تونل هم‌نام رد می‌شود، نه یک سیم بلند؛ هر تونل با یک ساقه‌ی کوتاه (۳۰ واحد) به پایه‌ی واقعی‌اش وصل است. این یعنی هیچ سیمی مسیر بلندی طی نمی‌کند و هیچ دو سیمی که به هم ربطی ندارند از کنار هم رد نمی‌شوند — نکته‌ای که در README پروژه‌های CE103-CAL/Lab02 و Lab03 هم به‌عنوان تکنیک اصلی جلوگیری از تداخل بصری و اتصال‌کوتاه تصادفی معرفی شده.
- طبقات `full_adder` داخل `adder4`/`adder5` هر کدام ۳۰۰ واحد از هم فاصله دارند (در برابر جعبه‌ی ۸۰×۸۰ خود `full_adder`) — فاصله‌ی خیلی بیشتر از حد لازم، تا هیچ دو طبقه به‌هم نزدیک نشوند. همین الگو در `cmp3`/`eq5` (۱۵۰-۲۰۰ واحد بین گیت‌های یک ستون، ۳۰۰+ واحد بین ستون‌ها) و در `mod3_checker`/`mod11_checker` (۳۰۰-۶۰۰ واحد بین بلوک‌ها) تکرار شده.
- هر یک از ۸ مدار فایل (`full_adder`, `adder4`, `adder5`, `cmp3`, `eq5`, `mod3_checker`, `mod11_checker`, `main`) با یک بررسی‌گر هندسی خودکار (پورت‌شده از `build_circ.py` پروژه‌ی Lab03) چک شده — هم‌پوشانی هم‌راستای دو سیم از دو نت متفاوت، تماس نقطه‌ی انتهایی یک سیم با بدنه‌ی سیم دیگر، و برخورد جعبه‌ی محیطی قطعات. **روی هر ۸ مدار صفر مشکل گزارش شد.**

فایل با اسکریپت [`build_circ.py`](build_circ.py) تولید می‌شود:

```bash
python3 build_circ.py
```

## نکات پیاده‌سازی

- **هندسه‌ی گیت‌ها دوبار تأیید شده**: یک‌بار با استخراج از یک مدار واقعی و کارکن (`full_adder`/`adder2` در CE103-CAL/Lab02)، و یک‌بار مستقل با ساخت مدارهای پروب کوچک (یک `NOT Gate` تنها، یک AND+XOR دوتایی) و اجرای واقعی آن‌ها با `--test-vector` لاجیسیم — پیش از آنکه حتی یک خط از مدار اصلی نوشته شود. نتیجه: `AND/OR Gate` ورودی‌ها را در `(x-50, y∓20)` می‌گذارد، `XOR Gate` در `(x-60, y∓20)`، `NOT Gate` در `(x-30, y)`؛ خروجی همه‌ی گیت‌ها دقیقاً روی `loc` خودشان است.
- **پورت زیرمدار = افست از انکر**: برای هر بلوک، `<appear>` یک `<circ-port pin="LOCAL_X,LOCAL_Y" x="OFF_X" y="OFF_Y"/>` دارد؛ وقتی بلوک در `loc=(X,Y)` جای می‌گیرد، آن پورت دقیقاً در `(X+OFF_X, Y+OFF_Y)` مدار بالادستی ظاهر می‌شود — همان قراردادی که در `<circ-port>`های `multiplier` (CE103-CAL/Lab03) استفاده شده.
- منطق تقسیم‌پذیری («جمع ارقام mod 3»، «جمع متناوب ارقام mod 11») پیش از ساخت هر مداری با یک اسکریپت پایتون روی هر ۱۰۰۰۰ مقدار BCD brute-force تأیید شد؛ این یعنی وقتی بلوک‌های گیتی هم تک‌تک درست از آب درآمدند (full_adder/adder4/adder5/cmp3/eq5 هرکدام صد در صد پاس)، ترکیب‌شان هم بی‌درنگ ۱۰۰۰۰/۱۰۰۰۰ پاس شد — بدون هیچ دور اشکال‌زدایی.
